# 「考えなくていいUI」フレームワーク

ritar氏の「考えなくていいUIを考える」に基づくUI分析・設計フレームワーク。

## 核心概念

### 根本原理: 注意の代替

人間の注意は構造上、**一つずつ順番にしか意識を向けることができない**。大量のアイテムや複雑な構造を把握するときも、次に何を見るかを無意識に判断している。「考えなくていいUI」の本質は、この**注意の働きをUIが代替してくれる**こと — つまり、次に見るべき対象をシステムが決めてくれるから、ユーザーは「どこに注意を向けるか」を選ぶ必要がない。

### タイムライン的UI vs トポグラフィ的UI

|                | タイムライン的UI                                                          | トポグラフィ的UI                                         |
| -------------- | ------------------------------------------------------------------------- | -------------------------------------------------------- |
| **構造**       | 一直線                                                                    | 空間的・階層的・ネットワーク的                           |
| **注意の制御** | システムが誘導                                                            | ユーザーが自ら選択                                       |
| **管理**       | 不要（システムが自動で優先順位を「決めつけ」て整理）                      | 必要（ユーザーが手動で配置・整理しないと散逸する）       |
| **認知負荷**   | 低い（やることが明確すぎて遊びの余地がない）                              | 高い（次に何をするか自分で考える余地がある）             |
| **自由度**     | 低い                                                                      | 高い（探索・創造的）                                     |
| **弱点**       | 重要な情報も流れてしまう / 中毒性                                         | 管理コストが高い / 目的のアイテムに到達するまでの負荷    |
| **例**         | TikTok, Xフィード, Slackキャッチアップ, Apple メモ, iOSアプリスイッチャー | Googleドライブ, Notion, Figma, PCデスクトップ, Wikipedia |

**両者は連続的なスペクトラムであり、二項対立ではない。** どちらか片方に分類されるのではなく、どちらの度合いが強いか、どの側面を導入しているかという視点で見る。

### ストック/フローとの違い（重要な注意）

この枠組みは**情報の種類ではなく、見せ方（プレゼンテーション）の話**。情報マネジメントにおけるストック情報/フロー情報は情報自体の性質の区別だが、タイムライン/トポグラフィは純粋にUIの表示レイヤーの話。同じフロー情報（例: Slackのチャット）でも、チャンネル一覧はトポグラフィ的、キャッチアップはタイムライン的になる。この区別を混同しないこと。

### 管理コスト — なぜトポグラフィは「考える」UIなのか

タイムライン的UIは、システムが「新しいものほど重要だろう」と**決めつけ**て自動的に優先順位をつける。この決めつけのおかげで、ユーザーは何も考えなくても情報が一直線に並ぶ（例: Apple メモは書いた順に並び、古いものはスクロールの彼方に消える）。

一方トポグラフィ的UIには配置があり、古いものだからといって消えない。だから定期的にフォルダ分けして整理しないと、どこに何を置いたかわからなくなる（例: Notionは常にフォルダ構造を意識させられる）。この**管理の必要性**が、トポグラフィ的UIの認知負荷の本質的な原因の一つ。

### 「考えさせるUI」としてのトポグラフィの価値

トポグラフィ的UIは「考えなくていい」から遠いが、それは**メリットでもある**。タイムライン的UIはシステムが優先順位を押し付ける一方、トポグラフィ的UIは**ユーザーの自由な発想による探索を促す**。

Wikipediaを自由に探索する楽しさ、ホワイトボードに思い思いの場所に書き込む楽しさ — これは自分の外部の環境とのインタラクションを楽しむ、**オープンワールドゲーム**で遊んでいるような感覚。「次は何をやってみようか」と自分で考える余地があること自体が、創造性と密接に関わっている。

レビュー時、トポグラフィ的UIを安易にタイムライン化すべきでない場面を判断するために、この価値を意識すること。

## タイムライン的UIの4条件

UIの「考えなくていい」度合いを評価する4条件:

1. **アイテムが一直線に並んでいる** — リスト・カード・縦スクロールなど、順序が明確
2. **主な目的がリスト内で完結する** — 別画面に遷移せずに目的を達成できる
3. **見るべき順番にアイテムが並んでいる** — 時系列・おすすめ順など、システムが順序を決定
4. **見るべきでないものの視覚的優先度が低い** — 見終わったもの/未到達のものが画面外に押し出される

満たす条件が多いほど「考えなくていいUI」に近い。

## レビューワークフロー

### Step 1: 対象UIの分類

対象のUIが以下のどちらに近いか判定する:

- **タイムライン寄り**: フィード、通知一覧、メッセージストリーム、ウィザード
- **トポグラフィ寄り**: ダッシュボード、ファイルブラウザ、設定画面、ホワイトボード
- **混合型**: サイドバー（トポグラフィ）+ メインエリア（タイムライン）

### Step 2: 4条件チェック

タイムライン的UIの4条件をそれぞれ評価し、不足している条件を特定する。

```
[例: ECサイトの商品一覧]
条件1 一直線に並んでいる    → △ グリッドレイアウトで2次元的
条件2 リスト内で完結する    → × 商品詳細に遷移が必要
条件3 見るべき順番になっている → ○ おすすめ順ソート
条件4 見るべきでないものが低優先度 → ○ スクロールで隠れる
```

### Step 3: 目的適合性の判断

UIの目的に照らして、タイムライン化すべきかトポグラフィを維持すべきか判断する。

**タイムライン化が適するケース:**

- 大量アイテムの消費・処理（既読処理、承認フローなど）
- ユーザーに迷わせたくない操作フロー
- 繰り返し行う定型的なタスク
- 構造が深く/複雑で、目的のアイテムに到達するまでの認知負荷が高い場面

**トポグラフィを維持すべきケース:**

- 創造的な探索が目的 — 「次は何をやってみようか」という自由な発想を促したい場面（ホワイトボード、Wiki）
- 複数人での構造的な情報共有（社内Wiki、ドキュメント管理）— 管理コストをかけるだけの価値がある
- 空間的記憶や一覧性が重要な場面（ダッシュボード、横並び比較）
- 情報の永続性が求められる場面 — タイムラインでは重要な情報も流れてしまう
- 思考の深化が目的 — 時間とともにページ間リンクや情報の付け足しで構造を育てたい場面

## AI/LLMによる構造変換

記事の最も独創的な論点: **AIコーディングソフトは、AIがトポグラフィをタイムラインに変換してくれる装置**。

CursorやClaude Codeでは、左側にトポグラフィ的なコードエディタ（フォルダ構造をそのまま表示）、右側にタイムライン的なチャット欄が並ぶ。通常のソフトウェア開発では「どのファイルを開くか→リンク先に飛ぶ→違った→階層を遡る」とトポグラフィの中を自力で探索する必要があるが、AIとのチャットでは**自分の思ったことを思った順番にタイムラインに記していけば、AIが適宜注意力を使って多数のファイルを編集してくれる**。これが「バイブコーディング＝考えなくていいコーディング」の正体。

この議論はコーディングに限らない。Excel Copilot（複雑な表というトポグラフィをチャットから遠隔操作）、PDFの読解、プレゼン作成など、**注意を向ける先を考えながら行わなければならない複雑な作業全般でAIによるトポグラフィのタイムライン化が適用可能**。

ただし「すべてがタイムライン化する」のではなく、**基盤としてトポグラフィがあって、それをタイムライン的に操作できる**という関係。レビュー時は、AIによる変換が適切な場面かどうかも考慮すること。

## トポグラフィ→タイムライン変換パターン

既存のトポグラフィ的UIを「考えなくていい」方向に改善する代表的パターン:

- **カード化**: 入れ子構造をフラットなカードリストに変換（例: Slackキャッチアップ）
- **AIチャット経由の操作**: トポグラフィ的な構造をチャットUIで操作可能にする（例: Cursor, Excel Copilot）
- **スマートフィード**: 複数ソースの情報を優先順位付きの単一フィードに統合
- **ウィザード化**: 複雑な設定画面をステップバイステップに変換

## タイムライン→トポグラフィ逆変換

タイムラインには「複雑な構造を表現できない」「重要な情報もすぐ流れてしまう」「中毒性がある」という弱点がある。これを補うためにトポグラフィへの逆変換が必要になる場面がある。

- **ブックマーク/ピン留め**: タイムラインから重要アイテムを抜き出し永続化
- **デジタルガーデン化**: フィードの流れから離れ、自分で構造化して思考を深める場所を作る
- **ダッシュボード集約**: タイムラインの要約・集計を空間的に俯瞰

Slackはこの往復の好例: もともとタイムライン的なチャットに、チャンネルというトポグラフィ的構造を導入し、さらにキャッチアップでそれをタイムライン的に消費するUIを導入し直した。

詳細な改善パターンは [references/improvement-patterns.md](references/improvement-patterns.md) を参照。
