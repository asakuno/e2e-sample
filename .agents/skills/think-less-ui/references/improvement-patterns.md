## ケーススタディ

レビュー時に参照できる具体的な分析事例。

### ケース1: メモアプリ — Apple メモ vs Notion

**Apple メモ（タイムライン的）**: 書いたメモが時系列に並ぶ。最新が一番上、古いものは下に流される。一直線のリスト・明確な順番付け・古いものが流される点でタイムライン的。管理は不要 — システムが「新しいものほど重要」と決めつけて自動整理する。

**Notion（トポグラフィ的）**: フォルダ構造を持ち、ページの中に子ページを作れる。配置があるため古いものも消えない。だが定期的にフォルダ分けして整理しないと、どこに何を置いたかわからなくなる。

**教訓**: タイムライン的UIの「考えなくてよさ」は、管理の不要さからも来ている。ただしNotionには「管理コストをかければ、誰が見てもわかりやすいトピックベースの整理ができる」という、大人数利用（社内Wikiなど）に不可欠な利点がある。

### ケース2: ウィンドウ管理 — iOSアプリスイッチャー vs macOSデスクトップ

**iOSアプリスイッチャー（タイムライン的）**: 最近使ったアプリが時系列で並ぶ。「最近使ったものほど次に開く可能性が高い」という決めつけで自動整理。管理不要 — アプリを開きすぎたから閉じなきゃ、とはならない。古いものは気にも留めず忘れていく、人間の意識の延長のようなUI。

**macOSデスクトップ（トポグラフィ的）**: ウィンドウに位置・大きさがある。自分が閉じない限り消えない。開きすぎると管理の必要が生じ、今のタスクに関係あるウィンドウを探すのに時間がかかる。一方、一覧性が高く、横並び比較や空間的記憶が活かせる。

**教訓**: ストック/フローの区分では捉えられない例。ウィンドウは蓄積される情報ではないが、タイムライン/トポグラフィの枠組みなら分析できる（見せ方の軸だから）。

### ケース3: Slackの往復変換

Slackの歴史は変換の繰り返し:

1. もともとチャットは一直線のタイムライン
2. Slackはチャンネルというトポグラフィ的構造を導入（トピックごとのフォルダ分け）
3. しかしチャンネルが増えすぎて「どこから見るか」の認知負荷が増大
4. キャッチアップでトポグラフィをタイムライン的に消費するUIを導入し直した

**教訓**: タイムラインとトポグラフィは一方通行ではなく往復する。スケールや文脈に応じて適切な方向に変換することが重要。

## トポグラフィ→タイムライン変換パターン

UIの認知負荷を下げ、「考えなくていい」方向に改善するパターン。

### パターン1: カードスタック化

入れ子構造（一覧→詳細）をフラットなカードに変換し、スワイプ/スクロールで消費する。

**Before**: チャンネル一覧 → チャンネルを選択 → メッセージを読む
**After**: カードに要約が表示され、左右スワイプで処理

**適用条件**: 各アイテムの情報量が少なく、カード1枚に収まる場合
**実例**: Slackキャッチアップ、Tinderライクな承認UI

### パターン2: スマートフィード統合

複数のソース（フォルダ、カテゴリ、チャンネル等）からの情報を、優先順位付きの単一フィードに統合する。

**Before**: カテゴリA、カテゴリB、カテゴリC を個別に巡回
**After**: 全カテゴリの重要なアイテムが優先度順に1つのフィードに並ぶ

**適用条件**: ユーザーが複数ソースを横断的に確認する必要がある場合
**実例**: GitHubの通知フィード、Googleの「おすすめ」フィード

### パターン3: AIチャット経由の操作（トポグラフィのタイムライン化）

トポグラフィ的な構造をチャットUIから遠隔操作可能にする。ユーザーは構造に直接触れず、タイムライン的なチャットから指示を出す。これは単なる便利機能ではなく、**AIがトポグラフィをタイムラインに変換してくれる装置**として機能している。

**Before**: ファイルツリーを辿って目的のファイルを探す。どのファイルを開くか→リンク先に飛ぶ→違った→階層を遡る、と注意を向ける先を常に考える必要がある
**After**: 「○○に関するファイルを全部教えて」とチャットで指示。自分の思ったことを思った順番にタイムラインに記していけば、AIが適宜注意力を使って多数のファイルを編集してくれる

**適用条件**: 構造が深い/複雑で、目的のアイテムに到達するまでの認知負荷が高い場合
**実例**: Cursor/Claude Code（コードベースというトポグラフィをチャットから操作）、Excel Copilot（複雑な表をチャットから遠隔操作）
**注意**: 基盤としてトポグラフィは残り続ける。「すべてがタイムライン化してトポグラフィがなくなる」のではなく、トポグラフィ的な構造をタイムライン的に操作できるようになるということ

### パターン4: ウィザード化

複数の設定項目が一画面にある構成を、ステップバイステップの直線的フローに変換する。

**Before**: 設定画面に20個の項目が一度に表示される
**After**: 3ステップのウィザードで、各ステップ5-7項目ずつ表示

**適用条件**: 設定項目間に依存関係がある、または初回設定時の負荷を下げたい場合

### パターン5: インライン展開

一覧から詳細画面に遷移する構造を、一覧内で詳細をインライン展開する方式に変換する。

**Before**: メール一覧 → メールを選択 → 詳細画面に遷移
**After**: メール一覧でクリックするとその場で本文が展開される

**適用条件**: 条件2「リスト内完結」を満たしたい場合
**実例**: GmailのプレビューPanel、Slackのスレッド展開

## タイムライン→トポグラフィ変換パターン

タイムラインには「複雑な構造を表現できない」「どんなに重要なことも流れていってしまう」「何も考えなくてよいせいで中毒性がある」という本質的な弱点がある。これらを補うために、タイムラインからトポグラフィへの逆変換が必要になる。

### パターン6: ブックマーク/ピン留め

タイムラインの中から重要なアイテムを抜き出し、永続的な場所に配置する。

**課題**: 重要な情報がフィードの中を流れて見失う。半年前に話題だったニュースが、どんなに自分に関係あっても全く目にすることがなくなる
**解決**: ピン留め、ブックマーク、「後で読む」機能
**実例**: Slackのピン留め、Xのブックマーク

### パターン7: デジタルガーデン化

タイムライン的に流れてくる情報を、自分で構造化して配置・蓄積する場所を用意する。「デジタルガーデン」とは、タイムラインの流れに一喜一憂するソーシャルメディアとは別に、自分用に考えを整理して保管する場所＝「デジタルな庭」を作ろうという試み。

**課題**: タイムラインでは思考の深化ができない。最近起こったことでフィードが埋め尽くされ、すぐに忘れ去られていく
**解決**: Wiki的なページ間リンク構造、自由配置のキャンバス。タイムラインから一部を切り取って「配置」し、後からまた訪れて他のページとつないだり情報を付け足したりして、時間とともに思考を深めていく
**実例**: Obsidian（グラフビューでリンクの全体像を俯瞰）、Scrapbox/Cosense、Notion
**背景**: 実は「タイムライン」「トポグラフィ」という用語自体がデジタルガーデン実践者のブログからの拝借。トポグラフィ＝「地形」 — 流されずにとどまり続ける、配置を持ったシステムを表す

### パターン8: ダッシュボード集約

タイムラインの要約・集計をトポグラフィ的な一覧画面で俯瞰する。

**課題**: 個別のフィードアイテムを追っているだけでは全体像が見えない
**解決**: KPI、グラフ、サマリーを空間的に配置したダッシュボード
**実例**: GitHub Insights、Slackのアナリティクス

## 条件別の改善テクニック

### 条件1「一直線」を改善する

- グリッドレイアウト → 1カラムリストに変更
- タブ切り替え → 縦スクロールの連続表示に変更
- ページネーション → 無限スクロールに変更

### 条件2「リスト内完結」を改善する

- 詳細画面への遷移 → インライン展開/プレビューパネル
- モーダルダイアログで詳細表示
- カード内に必要十分な情報を含める

### 条件3「順番付け」を改善する

- 手動並び替え → アルゴリズムによる自動ソート
- 更新日時順、優先度順、AI推薦順の導入
- 「おすすめ」「あなたへの通知」等のパーソナライズ

### 条件4「視覚的優先度」を改善する

- 既読/完了アイテムのグレーアウトまたは非表示
- 未読バッジ、ハイライト表示
- スクロールによる自然な優先度付け
- 「アーカイブ」「完了」で画面から除外

## 実例集

### 通知・受信箱系

| サービス     | 現状                             | 改善の方向                           |
| ------------ | -------------------------------- | ------------------------------------ |
| メール受信箱 | トポグラフィ寄り（フォルダ構造） | Gmail「重要な新着」→ タイムライン化  |
| GitHub通知   | 混合型                           | フィルタ付きフィードでタイムライン化 |
| Slack        | トポグラフィ（チャンネル一覧）   | キャッチアップでタイムライン化       |

### 管理画面系

| 画面タイプ     | 推奨アプローチ                              | 理由                                   |
| -------------- | ------------------------------------------- | -------------------------------------- |
| タスク管理     | 混合型（リスト + ボード）                   | 消化はタイムライン、俯瞰はトポグラフィ |
| ファイル管理   | トポグラフィ（+ 検索/AI支援）               | 構造の永続性が重要                     |
| 承認フロー     | タイムライン（カードスタック）              | 順番に処理するだけ                     |
| ダッシュボード | トポグラフィ                                | 一覧性・空間的記憶が重要               |
| 設定画面       | 混合型（初回ウィザード + 後から全項目表示） | 初回の負荷軽減 + 後からの細かい調整    |

### コンテンツ消費系

| タイプ         | タイムライン度       | 注意点                       |
| -------------- | -------------------- | ---------------------------- |
| ショート動画   | 極めて高い           | 中毒性に注意                 |
| SNSフィード    | 高い                 | 重要情報が流れる問題         |
| ニュースサイト | 中程度               | カテゴリ構造とフィードの共存 |
| Wikipedia      | 低い（トポグラフィ） | 探索的な学習に適する         |
