# Test Methodology Reviewer

## 利用タイミング

本スキルは**既存テストコードのレビュー**に使用する。テスト仕様書の作成には使用しない。

| フェーズ | 使用可否 | 説明 |
|---------|---------|------|
| E2Eテスト仕様書作成 | **使用しない** | `designing-e2e-specs` が技法知識を内包済み |
| E2Eテスト実装後のレビュー | **推奨** | 実装済みテストコードの品質を評価 |
| Unit/Featureテストのレビュー | **推奨** | テスト設計技法の適用を評価 |
| カバレッジ改善の相談 | **推奨** | カバレッジ戦略の提案 |

## References

必要に応じて以下を読み込むこと:

- **技法選択が必要な場合**: `references/technique-selection.md`
- **Unit テストのレビュー時**: `references/unit-test-patterns.md`
- **E2E テストのレビュー時**: `references/e2e-test-patterns.md`
- **カバレッジ改善時**: `references/coverage-strategies.md`

## Workflow

1. 対象テストコードとソースコードを読む
2. テストレベルを判定する（Unit / Integration / E2E）
3. 該当する references を読み込む
4. Review Checklist に基づいてレビュー実施
5. 改善提案をリスト化して出力

## Review Checklist

### Unit テストのレビュー

- [ ] **同値分割**: 入力値を有効/無効クラスに分割してテストしているか
- [ ] **境界値**: 境界値（最小、最小-1、最大、最大+1）をテストしているか
- [ ] **AAA パターン**: Arrange-Act-Assert の構造になっているか
- [ ] **単一責務**: 1テスト1アサーションを守っているか
- [ ] **Mock/Stub**: 外部依存を適切にモック化しているか
- [ ] **ブランチカバレッジ**: 条件分岐の両方のパスをテストしているか
- [ ] **エラーケース**: 異常系・例外をテストしているか

### Integration テストのレビュー

- [ ] **コンポーネント結合**: 依存コンポーネント間の結合をテストしているか
- [ ] **データフロー**: データの流れを正しくテストしているか
- [ ] **トランザクション**: DB トランザクションの挙動をテストしているか
- [ ] **外部サービス**: 外部APIとの連携をテストしているか

### E2E テストのレビュー

- [ ] **ユーザーシナリオ**: 実際のユーザー操作をシミュレートしているか
- [ ] **状態遷移**: 画面遷移を網羅的にテストしているか
- [ ] **Page Object**: POM パターンを使用しているか
- [ ] **安定性**: 非同期処理を適切に待機しているか
- [ ] **データ独立性**: テスト間でデータが独立しているか
