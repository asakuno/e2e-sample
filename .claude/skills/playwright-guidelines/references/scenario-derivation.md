# 画面遷移図・アクティビティ図からの E2E シナリオ導出

Phase 1（`/designing-e2e-specs`）で、**図から再現可能に E2E シナリオを起こす**ための手順。場当たり的にシナリオを思いつくのではなく、遷移を基準に網羅を設計し、E2E(Large) に残すものだけを絞り込む。

## 入力

| 図 | そこから得るもの |
|----|------------------|
| **画面遷移図** | 状態（＝画面）と遷移（＝操作・イベント）。シナリオの骨格 |
| **アクティビティ図** | 各操作の前提条件・分岐・事後条件。シナリオの肉付け |
| （あれば）状態遷移図 / ユースケース | 状態の網羅基準・利用者の目的 |

画面遷移図が無い場合は、まず `screen-design-process` で画面構成を整理してから本手順に入る。

## 導出手順

1. **状態と遷移を抽出**: 画面遷移図をノード（画面）＋エッジ（操作/イベント）として書き出す。
2. **前提・事後条件を補完**: 各エッジに、アクティビティ図から前提条件（必要なデータ・権限）と事後条件（期待される結果）を付与する。
3. **パスを列挙**: 開始状態 → 終了状態までの「操作可能な手順列（パス）」を洗い出す。
4. **網羅基準を決める**: [遷移網羅の基準](#遷移網羅の基準)から、最低限の目標を選ぶ。
5. **E2E(Large) へ昇格するパスを選定**: すべてのパスを E2E にしない。[E2Eに昇格する判断](#e2eに昇格する判断)で代表に絞る。
6. **テストケース化**: 選んだシナリオを[テンプレート](#テストケース化のテンプレート)に落とし、テスト仕様書（Markdown表）へ反映する。

## 遷移網羅の基準

状態遷移テストの網羅基準を、遷移（エッジ）に対して適用する。

| 基準 | 内容 | E2Eでの位置づけ |
|------|------|----------------|
| **0スイッチ（全状態）** | すべての画面に最低1回到達 | 最低限。到達不能画面の検出 |
| **1スイッチ（全遷移）** | すべての遷移（エッジ）を1回ずつ通る | **E2Eの基本網羅目標**。ただし代表シナリオへ集約 |
| **Nスイッチ / 全パス** | 連続する遷移列・全経路を網羅 | 重要フローのみ。**組合せ爆発に注意**し、E2Eでは原則採らない |

> 詳細な技法背景（状態遷移テスト・デシジョンテーブル）は `test-methodology-reviewer` の `references/technique-selection.md` を参照。

## E2Eに昇格する判断

導出したパスのうち、**E2E(Large) に残すのは限定する**。判断軸は `test-methodology-reviewer` の[テストサイズ／リスクベース選定](../../test-methodology-reviewer/references/coverage-strategies.md#15-テストサイズtest-sizeでレベルを判断する)に従う。

- **E2E(Large) に残す**: ユーザー価値の高い代表シナリオ / 統合境界 / Happy path / 重大リスク経路
- **E2E に積まない（下位レベルへ落とす）**: 入力条件の組み合わせ・分岐ロジック → Small/Medium で[原因結果グラフ→デシジョンテーブル](../../test-methodology-reviewer/references/technique-selection.md#原因結果グラフceg-デシジョンテーブル)等により網羅
- **データ準備も Large 相応に明示**: 各シナリオの前提データは `laravel-test-data-setup.md` の `laravel.factory` / `laravel.scenario` で用意する

「同一機能を Small/Medium/Large でどう切り分けるか」の具体例は coverage-strategies.md の [worked example](../../test-methodology-reviewer/references/coverage-strategies.md#worked-example-同一機能を3サイズで切り分ける) を参照。

## テストケース化のテンプレート

選定したシナリオは、画面単位のテスト仕様書（`SKILL.md` のフォーマット）へ次の粒度で落とす。

| 項目 | 内容 | 補足 |
|------|------|------|
| 前提条件 | テストデータ（factory/scenario）・認証状態 | `laravel-test-data-setup.md` |
| 操作手順 | 画面遷移のエッジ列（操作を順に） | アクティビティ図の分岐に沿う |
| 期待結果 | 各ステップの観測可能な結果 | **仕様（テストベース）に根拠づくこと**。`code-generation-checklist.md` の §0 を参照 |
| 優先度 | 高/中/低 | 高＝クリティカルパス |

## 注意点（組合せ爆発・AI生成）

- **全パスを E2E 化しない**。1スイッチ網羅を超える組合せは下位レベルへ。重複する E2E は代表シナリオへ集約する。
- **AI にシナリオ生成させる場合**、出力された期待結果が仕様に根拠づくか（一般知識による捏造でないか）を必ずレビューする。`code-generation-checklist.md` の §0「AI生成テストの意味的妥当性」を適用する。
