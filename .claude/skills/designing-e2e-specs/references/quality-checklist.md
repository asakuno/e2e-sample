# 品質チェック — 報告フォーマットと修正指示例

チェック項目の一覧は SKILL.md の [6/7] セクションを参照。
本ファイルは報告時のフォーマットと不合格時の修正指示例を提供する。

## 不合格時の修正指示テンプレート

| # | 修正指示 |
|---|---------|
| 1 | 「{導線名}の正常系E2Eテストを追加してください」 |
| 2 | 「{導線名}の高リスク異常系E2Eテストを追加してください」 |
| 3 | 「以下のクリティカル導線のE2Eテストが不足: {導線リスト}」 |
| 4 | 「以下のバリデーション要件の割当が不足: {ルールリスト}」 |
| 5 | 「責務マトリクスを見直してください。{要件名}は{推奨層}への委譲が適切です」 |
| 6 | 「技法選定結果を追記してください。判定条件と採用理由を明記してください」 |

## 品質チェック報告フォーマット

品質チェック結果は以下の形式でユーザーに報告する:

```
【トレーサビリティ確認】
- 総要素数: X件
- テスト紐付け済み: Y件
- 未テスト要素: Z件（リスト表示）

【責務分類確認】
- 要件総数: X件
- E2E分類: Y件
- Feature分類: Z件
- Unit分類: W件
- 責務分類の妥当性: ✓/✗
- 技法選定根拠: 明確✓/不十分✗
- 状態遷移一覧（該当時）: 整備済み✓/不足✗
- 条件組み合わせ要約（該当時）: 整備済み✓/不足✗
- 非E2E詳細混入: なし✓/あり✗

【カバレッジ確認】
- クリティカル導線E2E: X件（Y件中Y件カバー）✓/✗
- 高リスク異常系: Z件 ✓/✗
- 境界値（E2E対象）: W件 ✓/✗
- バリデーション要件の全層割当: A/B件 ✓/✗

【具体性確認】
- 前提条件: 具体的✓/要改善✗
- 操作手順: 具体的✓/要改善✗
- 期待結果: 具体的✓/要改善✗

【品質スコア】: XX% (合格/条件付き合格/不合格)
```

---

## 修正指示の出力例

```markdown
## 品質チェック結果: 不合格（スコア: 57%）

### 修正が必要な項目

#### 1. バリデーション要件の全層割当100% ✗
**問題**: パスワード入力欄の文字数バリデーションにテスト割当がない
**修正指示**: 「以下のバリデーション要件の割当が不足: パスワード8文字以上」
**追加すべき割当例**:
- Feature: `tests/Feature/Http/Requests/Auth/RegisterRequestTest.php`
- E2E（必要な場合のみ）: `tests/e2e/specs/auth/register.spec.md`

#### 2. 前提条件の具体性 ✗
**問題**: 「ログイン済み」という曖昧な記述
**修正指示**: 「前提条件を具体化してください」
**修正例**:
- Before: 「ログイン済み」
- After: 「email: test@example.com, password: password123 でログイン済み、ダッシュボード画面 (/dashboard) を表示」

#### 3. トレーサビリティ完全性 ✗
**問題**: 以下のE2E対象要素にテストが紐付けられていない
**未テスト要素**:
- ELM-005: パスワードリセットリンク（ナビゲーション）
- ELM-006: 新規登録リンク（ナビゲーション）
```
