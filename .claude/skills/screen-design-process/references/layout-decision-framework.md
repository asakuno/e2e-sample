# レイアウト選定フレームワーク

画面に表示する情報の特性に基づいて、最適なレイアウトを選定するためのガイド。

---

## 判断フローチャート

以下の質問に順番に答えていく:

```
Q1: データの比較・ソートが重要か？
  → Yes: Q2へ
  → No:  Q3へ

Q2: 1アイテムの属性が5つ以上あるか？
  → Yes: テーブル（ただし画像が主体ならカード、モバイルファーストならリスト検討）
  → No:  リスト（ソート可能）
  ※ 属性数だけでなく、属性の種類（テキスト/数値→テーブル向き、画像/リッチコンテンツ→カード向き）
    アクションの多さ（一括操作→テーブル向き、個別操作→カード向き）も考慮する

Q3: 画像やビジュアルが主役か？
  → Yes: Q4へ
  → No:  Q5へ

Q4: アイテム間の均一性が高いか？
  → Yes: グリッド
  → No:  カード（不定形）

Q5: 一覧と詳細を同時に見たいか？
  → Yes: マスター/詳細
  → No:  Q6へ

Q6: 時系列や順序が重要か？
  → Yes: リスト（縦）
  → No:  カード
```

---

## 各レイアウト詳細

### テーブル（Table）

**特徴**:
- 構造化データの比較に最適
- ソート・フィルタ・一括操作との相性が良い
- 情報密度が高い

**ベストケース**:
- 管理画面の一覧（ユーザー管理、注文管理）
- 比較が必要なデータ（価格比較、スペック比較）
- 一括操作が必要（チェックボックス+一括削除/更新）
- データのエクスポートを想定（CSV出力等）

**ワーストケース**:
- 項目が3つ以下（テーブルの意味がない）
- 画像が主役のコンテンツ（商品カタログ等）
- モバイルファーストの画面（横スクロール発生）
- 各行の高さが大きくバラつくデータ

**ユースケース**:
- ユーザー管理画面（名前、メール、ロール、最終ログイン、ステータス）
- 注文一覧（注文番号、顧客、金額、日付、ステータス）
- ログ・監査画面（タイムスタンプ、アクション、ユーザー、詳細）
- 在庫管理（商品名、SKU、在庫数、入荷予定日）

### カード（Card）

**特徴**:
- 各アイテムが独立したまとまりとして認識される
- ビジュアル要素との相性が良い
- レスポンシブ対応が容易

**ベストケース**:
- 各アイテムが独立した単位（プロジェクト、チーム、商品）
- 画像+テキストの組み合わせ
- アイテム数が少〜中程度（〜50件）
- タッチ操作が主体

**ワーストケース**:
- 項目間の比較が必要
- 大量データの一覧（100件以上）
- 一括操作が主な用途
- 極端に情報が少ないアイテム

**ユースケース**:
- プロジェクト一覧（サムネイル、タイトル、進捗、メンバー）
- 商品カタログ（画像、名前、価格、評価）
- チームメンバー一覧（アバター、名前、役職、連絡先）
- ダッシュボードのKPIウィジェット

### リスト（List）

**特徴**:
- 最もシンプルで省スペース
- 時系列データとの相性が良い
- スキャンしやすい

**ベストケース**:
- 時系列データ（アクティビティログ、通知）
- 1アイテムの情報量が少ない
- 上から順に見ていく操作パターン
- ナビゲーション/メニュー

**ワーストケース**:
- 画像が重要なコンテンツ
- 複数属性の比較が必要
- アイテム間に視覚的な差が必要

**ユースケース**:
- 通知一覧（アイコン、タイトル、時刻）
- チャット/メッセージ一覧（アバター、名前、最新メッセージ、時刻）
- ファイルブラウザ（アイコン、ファイル名、サイズ、更新日）
- 設定項目一覧（ラベル、現在の値、トグル/リンク）
- 検索結果（タイトル、スニペット、URL）

### グリッド（Grid）

**特徴**:
- ビジュアルコンテンツの一覧に最適
- 一目で多くのアイテムを俯瞰できる
- ブラウジング（探索）に向いている

**ベストケース**:
- 画像が主役（写真、動画、デザイン）
- アイテム間の均一性が高い
- ブラウジング/探索が目的
- ビジュアルの比較

**ワーストケース**:
- テキスト情報が主体
- 各アイテムの高さが大きくバラつく
- 構造化データの比較
- 精密な操作が必要

**ユースケース**:
- 画像ギャラリー/ポートフォリオ
- アイコン/絵文字セレクター
- ダッシュボードタイル（均等サイズのウィジェット）

### マスター/詳細（Master-Detail）

**特徴**:
- 一覧と詳細を同時に表示
- コンテキストスイッチが少ない
- 広い画面で効果的

**ベストケース**:
- メールクライアントのような閲覧パターン
- 一覧を見ながら詳細を確認したい
- デスクトップ/タブレットの広い画面

**ワーストケース**:
- モバイル画面（幅が足りない）
- 詳細画面の情報量が少ない
- 一覧だけで完結する操作

**ユースケース**:
- メール/メッセージアプリ（左: 受信一覧、右: メール本文）
- ファイルマネージャー（左: フォルダツリー、右: ファイル一覧）
- 設定画面（左: カテゴリ、右: 設定項目）
- ドキュメント管理（左: 文書一覧、右: プレビュー）

## ハイブリッドパターン

実際の画面では、複数のレイアウトを組み合わせることが多い。

### カード + テーブル
```
用途: ダッシュボード
上部: KPIカード（4枚横並び）
下部: 詳細テーブル（最新の取引一覧）
```

### リスト + カード
```
用途: メッセージアプリ
左パネル: 会話リスト
右パネル: メッセージカード（吹き出し形式）
```

### グリッド + モーダル詳細
```
用途: 画像ギャラリー
メイン: グリッド表示
クリック時: モーダルで詳細表示（ライトボックス）
```

### テーブル + 展開行
```
用途: 注文管理
メイン: 注文テーブル
クリック時: 行が展開して注文明細を表示
```

## レスポンシブでのレイアウト変換

画面幅に応じてレイアウトを変換する基本パターン:

| デスクトップ     | タブレット       | モバイル           |
| ---------------- | ---------------- | ------------------ |
| テーブル         | テーブル（列削減）| カード or リスト   |
| グリッド（4列）  | グリッド（3列）  | グリッド（2列）    |
| マスター/詳細    | マスター/詳細    | リスト → 詳細画面  |
| カード（3列）    | カード（2列）    | カード（1列）      |

**原則**: モバイルでテーブルの横スクロールは避ける。カードまたはリストに変換する。
