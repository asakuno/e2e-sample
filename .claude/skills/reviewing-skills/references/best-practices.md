# Skill Best Practices Checklist

## 1. Frontmatter (YAML)

### name
- [ ] 64文字以内である
- [ ] 小文字、数字、ハイフンのみ使用している
- [ ] 動名詞形（-ing）を使用している（例: `processing-pdfs`）
- [ ] 曖昧な名前を避けている（`helper`, `utils`, `tools`はNG）
- [ ] 予約語を含まない（`anthropic`, `claude`はNG）

### description
- [ ] 1024文字以内である
- [ ] 空でない
- [ ] 三人称で記述している（「I can help」ではなく「processes files」）
- [ ] `[What] + [When] + [Key capabilities]` の3要素構造を満たしている
  - What: スキルが何をするか
  - When: いつ使うべきか（トリガー条件）
  - Key capabilities: 主要な機能リスト
- [ ] 具体的なトリガーフレーズを含んでいる
  - 良い例: 「PDFの作成」「フォーム入力の自動化」「コードレビュー」
  - 悪い例: 「ファイル処理」「データ操作」「ヘルプ」
- [ ] ネガティブトリガーを含んでいる（使うべきでないケースの明示）
  - 例: 「単純なテキストファイルの読み取りには使用しない」
- [ ] ファイル形式やタスクタイプを明示している

### allowed-tools（オプション）
- [ ] 使用するツールが制限されている場合、明示的にリストしている
- [ ] 不要なツールアクセスを制限してセキュリティを向上させている

### compatibility（オプション）
- [ ] 対応プラットフォームを明記している（claude.ai, claude-code, api等）

### metadata（オプション）
- [ ] `author` が記載されている（推奨）
- [ ] `version` が記載されている（推奨）
- [ ] 依存するMCPサーバーが `mcp-server` で記載されている（該当する場合）

## 2. フォルダ構造

- [ ] フォルダ名がkebab-caseである
- [ ] SKILL.mdのファイル名が正確（大文字小文字厳密: `SKILL.md`）
- [ ] README.mdをスキルフォルダ内に含んでいない（SKILL.mdのみ使用）
- [ ] サブディレクトリ構成が適切（`scripts/`, `references/`, `assets/`）
- [ ] 不要なファイルが含まれていない

## 3. SKILL.md Body

### 簡潔さ (Conciseness)
- [ ] 500行以下である
- [ ] 推定5,000語以下である
- [ ] Claudeが既に知っている情報を含まない
- [ ] 冗長な説明より簡潔な例を優先している
- [ ] 各情報がトークンコストに見合う価値がある

### 構造
- [ ] 重要な指示がボディの上部に配置されている
- [ ] 明確なセクション分けがある
- [ ] 目次またはナビゲーションがある（長い場合）
- [ ] 「When to Use This Skill」セクションがbodyにない（descriptionに含めるべき）

### 表現の明確さ
- [ ] 曖昧な表現を避けている
  - NG: 「適切に処理する」「必要に応じて対応する」「良い感じにする」
  - OK: 「UTF-8エンコーディングで出力する」「エラー時はstderrに出力する」「3回リトライ後に失敗とする」
- [ ] 具体的な数値・条件・基準を提示している

### Progressive Disclosure（3レベルシステム）
- [ ] **Level 1（frontmatter）**: トリガー判定に必要な最小限の情報のみ
- [ ] **Level 2（SKILL.md body）**: 完全な指示とガイダンス
- [ ] **Level 3（参照ファイル）**: 必要時のみ読み込まれる詳細情報
- [ ] 詳細な情報は別ファイルに分離している
- [ ] 参照ファイルへのリンクが1階層深さまで
- [ ] 参照ファイルの用途が明確に説明されている
- [ ] 100行以上の参照ファイルには目次がある

## 4. Workflows

### ワークフロー設計
- [ ] 複雑な操作は明確な順序のステップに分解している
- [ ] チェックリスト形式で進捗を追跡できる
- [ ] 条件分岐が明確に記述されている
- [ ] 決定ポイントで明示的なガイダンスがある

### ワークフローパターンの認識
以下の5パターンのうち、適切なものを採用しているか確認:
- [ ] **Sequential**: 直線的なステップ実行（基本パターン）
- [ ] **Multi-MCP**: 複数MCPサーバーを連携させるオーケストレーション
- [ ] **Iterative**: 実行→検証→修正のフィードバックループ
- [ ] **Context-Aware**: 環境・状態に応じた動的な分岐
- [ ] **Domain-Specific**: 特定ドメインの専門知識を適用

### バリデーション
- [ ] 重要な操作後に検証ステップがある
- [ ] 「実行→検証→修正→繰り返し」のフィードバックループがある
- [ ] エラーメッセージが具体的で問題箇所を特定できる

## 5. Scripts

### スクリプト品質
- [ ] エラー条件を明示的に処理している
- [ ] 定数に説明コメントがある（マジックナンバー禁止）
- [ ] 依存パッケージがSKILL.mdに記載されている
- [ ] プラットフォーム制限が明記されている

### ファイルパス
- [ ] フォワードスラッシュを使用している（`scripts/helper.py`）
- [ ] Windowsスタイルのパスを使用していない（`scripts\helper.py`はNG）
- [ ] ファイル名が内容を示す説明的な名前である

## 6. References

### 参照ファイル構成
- [ ] ドメインまたは機能ごとに整理されている
- [ ] 必要な時だけ読み込まれるよう設計されている
- [ ] SKILL.mdと情報が重複していない

## 7. Content Quality

### 用語と言語
- [ ] 一貫した用語を使用している（同義語の混在を避ける）
- [ ] 時間に敏感な情報を含まない
- [ ] 命令形/不定詞形で記述している

### 例とテンプレート
- [ ] 具体的な入出力例がある
- [ ] 基本と応用の両方の例がある
- [ ] 例のスタイルが一貫している
- [ ] データ形式にはstrictテンプレート、創造的タスクにはflexibleテンプレートを使用

## 8. テスト品質

### トリガーテスト
- [ ] 意図したフレーズでスキルが起動するか確認済み
- [ ] 意図しないフレーズで誤起動しないか確認済み
- [ ] 類似スキルとの競合がないか確認済み

### 機能テスト
- [ ] 基本的なユースケースで期待通りの結果が得られるか確認済み
- [ ] エッジケースでの動作が確認済み
- [ ] エラー時の挙動が適切か確認済み

### パフォーマンス
- [ ] スキルなしの場合と比較して品質が向上しているか確認済み
- [ ] トークン使用量が妥当か確認済み（Progressive Disclosureの効果）

## 9. Composability（共存性）

- [ ] 他のスキルと同時に読み込まれても競合しない
- [ ] スコープが明確に定義されている（責務の境界が明確）
- [ ] グローバルな設定や状態を上書きしない
- [ ] 他スキルの機能と重複する場合、descriptionで棲み分けが明示されている

## 10. MCP Tools

- [ ] 完全修飾ツール名を使用している（`ServerName:tool_name`）
- [ ] サーバープレフィックスを省略していない

## 11. Anti-Patterns (避けるべきこと)

### 構造
- [ ] 全コンテンツをSKILL.mdにインラインで詰め込んでいない（Progressive Disclosure活用）
- [ ] 深くネストしたファイル参照がない
- [ ] README.mdをスキルフォルダに含んでいない

### 内容
- [ ] デフォルトなしで多くの選択肢を提示していない
- [ ] 1つのデフォルトで十分な時に複数のアプローチを提示していない
- [ ] 曖昧な説明やスキル名を使用していない
- [ ] 時間に敏感な情報を含まない
- [ ] 一貫性のない用語を使用していない
- [ ] Claudeが既に知っている情報を繰り返していない

### スクリプト
- [ ] Windowsスタイルのパスを使用していない
- [ ] パッケージがプリインストール済みと仮定していない
- [ ] マジック定数を説明なしで使用していない
- [ ] スクリプトでエラー条件を処理し忘れていない

### セキュリティ
- [ ] frontmatterにXMLタグを含んでいない
- [ ] スキル名に `claude` や `anthropic` を含んでいない

### Model Laziness対策
- [ ] 長い出力が必要な場合、省略防止の指示がある（例: 「全ステップを出力すること」）
- [ ] チェックリストやテンプレートは完全な形で提供されている

## 12. Troubleshooting（よくある問題）

### Over-triggering（誤起動が多い）
- descriptionのトリガーフレーズが広すぎないか確認
- ネガティブトリガーの追加を検討

### Under-triggering（起動しない）
- descriptionに十分なトリガーフレーズがあるか確認
- 具体的なユースケースを追加

### Instructions Not Followed（指示が無視される）
- 重要な指示がボディの上部にあるか確認
- 指示が曖昧でないか確認
- ボディが長すぎないか確認（5,000語以下推奨）

### Large Context Issues（コンテキスト肥大化）
- Progressive Disclosureが適切に使われているか確認
- 参照ファイルが必要時のみ読み込まれるか確認
- SKILL.md自体が長すぎないか確認

## Severity Levels

### Critical (必須修正)
- descriptionが空または不十分
- 500行を大幅に超えている
- セキュリティ上の問題がある
- スクリプトにエラー処理がない
- フォルダ構造が不正（SKILL.mdの名前が間違い等）

### Warning (推奨修正)
- Progressive Disclosureが適用されていない
- 例が不十分
- 用語の一貫性がない
- ワークフローが不明確
- descriptionに `[What] + [When] + [Key capabilities]` 構造がない
- Composabilityが考慮されていない
- ネガティブトリガーがない

### Info (改善提案)
- より簡潔にできる箇所がある
- 構造を改善できる
- 追加の例があると良い
- テスト品質の向上余地がある
- metadataフィールドの追加推奨
