# 実装仕様書: メール認証フロー追加

## 目的
既存のユーザー新規登録機能に、Laravel標準のメール認証フロー（MustVerifyEmail + 署名付きURL）を追加する。登録後はログイン状態だが、`verified`ミドルウェアで未認証ユーザーのアクセスを制限する。

## 要件
- [ ] 登録後にメール認証メールを自動送信
- [ ] 署名付きURLをクリックしてメール認証完了
- [ ] 認証メール再送機能
- [ ] `verified`ミドルウェアで未認証ユーザーのダッシュボードアクセスを制限
- [ ] メール認証待ちページ（Inertia）の表示
- [ ] 既存の登録フロー（UseCase、Repository等）との統合

## 技術仕様
- 言語: PHP 8.4+
- フレームワーク: Laravel 12.x
- 認証方式: Laravel標準 `MustVerifyEmail` + `Illuminate\Auth\Notifications\VerifyEmail`
- アーキテクチャ: 7層レイヤードアーキテクチャ（Laravel-native）
- 依存関係: 新規パッケージ不要（Laravel組み込み機能を使用）

## 実装手順（Phase単位で記載）

### Phase 1: Model層
- User Modelに`MustVerifyEmail`インターフェース実装
- `email_verified_at`カラムは既存（変更不要）

### Phase 2: UseCase層
- `RegisterUserUseCase`修正: 登録後にメール認証通知を送信
- `SendEmailVerificationUseCase`新規作成: 認証メール再送
- `VerifyEmailUseCase`新規作成: メール認証処理

### Phase 3: Controller・Request・Route層
- `EmailVerificationController`新規作成: 認証待ちページ表示、認証処理、再送
- `EmailVerificationRequest`新規作成: 署名付きURL検証
- ルート追加: `/email/verify`, `/email/verify/{id}/{hash}`, `/email/verification-notification`
- `verified`ミドルウェアをダッシュボードルートに適用

## 完了条件
- [ ] 登録後にメール認証メールが送信される
- [ ] 署名付きURLクリックで`email_verified_at`が設定される
- [ ] 未認証ユーザーはダッシュボードにアクセスできない（認証待ちページにリダイレクト）
- [ ] 認証メール再送が機能する
- [ ] PHPUnit テストがすべてパスする
- [ ] PHPStan、Pint、deptracがすべてパスする
