# バリデーションカバレッジフォーマット

## バリデーションルールの抽出手順

1. **仕様書からバリデーション一覧を抽出**
   - 「バリデーション」「エラーメッセージ」等のセクションを確認
   - 各入力項目のバリデーション条件をリスト化

2. **バリデーション種別ごとに担当レイヤーを決定する**

| バリデーション種別 | 主担当レイヤー | 補足 |
|------------------|--------------|------|
| **必須チェック** | Feature | 画面横断の主要導線のみE2Eにも追加可 |
| **文字数チェック** | Feature / Unit | 境界値ロジックが複雑な場合はUnit優先 |
| **形式チェック** | Feature | API/Form Requestでの検証を優先 |
| **範囲チェック** | Feature / Unit | 計算ロジックを含む場合はUnit追加 |
| **相関チェック** | Feature | 項目間整合性はHTTP境界での検証を優先 |
| **ファイルチェック** | Feature | 必要時のみE2EでUI表示確認を追加 |

3. **カバレッジ確認表を作成**

テスト仕様書に以下の形式でバリデーションカバレッジ表を含めること:

```markdown
## バリデーションカバレッジ

| No. | 項目名 | バリデーション種別 | 担当レイヤー | 対応テストID | 委譲先パス | カバー状況 |
|-----|--------|------------------|------------|-------------|-----------|----------|
| 1 | メールアドレス | 必須チェック | Feature | AUTH_REQ_001 | tests/Feature/Http/Requests/Auth/LoginRequestTest.php | ✓ |
| 1 | メールアドレス | 形式チェック | Feature | AUTH_REQ_002 | tests/Feature/Http/Requests/Auth/LoginRequestTest.php | ✓ |
| 2 | パスワード | 必須チェック | E2E | AUTH_LOGIN_ERR_001 | tests/e2e/tests/auth/login.spec.ts | ✓ |
| 2 | パスワード | 文字数チェック（8文字以上） | Feature | AUTH_REQ_003 | tests/Feature/Http/Requests/Auth/RegisterRequestTest.php | ✓ |

**カバレッジ率: X/Y件 (100%)**
```

## 記載粒度ルール

- E2E行: E2E仕様書に詳細手順・期待結果を記載してよい
- Feature/Unit行: E2E仕様書には委譲先の参照情報のみ記載する
- Feature/Unitの詳細ケースは、委譲先テストファイル側で管理する

## 品質ゲート

**バリデーション要件の全層割当100%未満の場合、品質チェックで不合格とする。**

不足している要件の担当レイヤーと委譲先パスを追加提案し、ユーザーに確認を求める。
