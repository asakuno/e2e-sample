# 株式投資支援Laravelアプリ 画面設計書

## 1. 本書の目的

本書は、株式投資支援LaravelアプリケーションのMVPにおける画面構成、画面ごとの役割、表示項目、画面遷移、UI方針を定義するものである。

本アプリケーションは、株式の保有管理や損益管理を目的とせず、ウォッチリストに登録した銘柄について、ニュース、株価、AI分析結果、シグナルスコアを確認し、売買判断に必要な材料を整理することを目的とする。

---

## 2. 前提条件

## 2.1 利用形態

本アプリケーションは、初期段階では個人利用を前提とする。

そのため、MVPでは以下の機能は対象外とする。

- 複数ユーザー向けの権限管理
- チーム管理
- ユーザー招待
- 課金機能
- 利用プラン管理
- 共有機能
- 公開プロフィール
- 管理者画面

ただし、将来的な拡張を考慮し、Laravelの認証機能は導入する。
ウォッチリスト、メモ、分析結果はユーザーに紐づけて管理する。

## 2.2 対象市場

MVPでは米国株を主対象とし、日本株は将来拡張を前提とする。

- 主対象: 米国株
- 副対象: 日本株
- 想定比率: 米国株 8 / 日本株 2

## 2.3 アプリケーションの位置づけ

本アプリケーションは以下を目的としない。

- 保有株管理
- 損益管理
- ポートフォリオ管理
- 証券会社API連携
- 自動売買
- 売買推奨

本アプリケーションは、以下を目的とする。

- ウォッチリスト銘柄の監視
- 株価材料の収集
- ニュースの要約
- ポジティブ/ネガティブ材料の整理
- シグナルスコアの確認
- 投資判断材料の蓄積

---

## 3. UI方針

## 3.1 UIコンセプト

UIは、Notion / 管理画面風のシンプルな構成とする。

特徴は以下とする。

- サイドバー型ナビゲーション
- カードレイアウト
- テーブル中心の情報整理
- タグによる状態表示
- フィルタによる絞り込み
- 落ち着いた配色
- 情報量が多くても読みやすいレイアウト

## 3.2 デザイン方針

本アプリケーションは、チャート中心の投資ツールではなく、材料分析中心のアプリケーションである。

そのため、画面上の優先度は以下とする。

1. AI分析サマリー
2. シグナルスコア
3. ポジティブ/ネガティブ材料
4. 関連ニュース
5. 株価チャート
6. 株価履歴

## 3.3 使用技術候補

- Laravel
- Blade
- Tailwind CSS
- DaisyUI
- Alpine.js または Livewire
- Chart.js または ApexCharts

MVPでは複雑なSPA構成にはせず、Bladeベースで実装する。

## 4. MVP画面一覧

MVPで実装する画面は以下とする。

| URL | 画面名 | 役割 |
|---|---|---|
| `/dashboard` | ダッシュボード | ウォッチリスト全体の状況確認 |
| `/stocks` | 銘柄一覧 | 銘柄検索・ウォッチリスト追加 |
| `/stocks/{symbol}` | 銘柄詳細 | AI分析・材料・ニュースの確認 |
| `/watchlists` | ウォッチリスト | 監視銘柄の管理 |
| `/news` | ニュース一覧 | ウォッチリスト関連ニュースの横断確認 |

## 5. MVP対象外画面

以下の画面はMVPでは対象外とする。

| URL | 画面名 | 理由 |
|---|---|---|
| `/alerts` | アラート | MVPでは通知機能を後回しにするため |
| `/signals` | シグナル一覧 | ダッシュボードで代替可能なため |
| `/settings` | 設定 | 個人用MVPでは優先度が低いため |
| `/admin` | 管理画面 | 個人利用前提のため |
| `/disclosures` | 開示一覧 | SEC/TDnet/EDINET連携は後続対応のため |

# 7. Dashboard画面

## 7.1 URL

```text
/dashboard
```

## 7.2 目的

アプリを開いたときに、ウォッチリスト全体の状況と、今日確認すべき銘柄・ニュースを把握する。

## 7.3 画面コンセプト

ハイブリッド型ダッシュボードとする。

上部にウォッチリスト全体のサマリー、中央に注目銘柄ランキング、下部に重要ニュースを表示する。

## 7.4 表示項目

### サマリーカード

- ウォッチリスト銘柄数
- 直近ポジティブ材料数
- 直近ネガティブ材料数
- 未分析ニュース数
- 最新分析日時

### 注目銘柄ランキング

- 銘柄コード
- 銘柄名
- 最新終値
- 前日比
- シグナルスコア
- センチメント状態
- 最終更新日時

### 重要ニュース

- 関連銘柄
- ニュースタイトル
- sentiment
- impact_score
- AI要約
- 配信元
- 公開日時

## 7.5 レイアウト案

```text
/dashboard

┌──────┬────────────┬────────┬────────┬────────────┐

├──────┼────────────┼────────┼────────┼────────────┤
```

## 7.6 操作

| 操作 | 遷移・挙動 |
|---|---|
| 銘柄コードをクリック | `/stocks/{symbol}` へ遷移 |
| ニュースをクリック | `/stocks/{symbol}` または `/news` の詳細表示へ遷移 |
| News一覧を見る | `/news` へ遷移 |

## 7.7 MVPで表示しないもの

- 保有株数
- 評価額
- 損益
- 資産推移
- 注文履歴
- 売買推奨

## 9.1 URL

```text
/stocks/{symbol}
```


## 9.2 目的

1つの銘柄について、AI分析、シグナルスコア、ポジティブ/ネガティブ材料、関連ニュースを確認する。

## 9.3 画面コンセプト

銘柄詳細画面は、チャート中心ではなく、AI分析・材料中心とする。

## 9.4 表示項目

### 銘柄ヘッダー

- 銘柄コード
- 銘柄名
- 市場
- 取引所
- セクター
- 通貨

### 株価カード

- 最新終値
- 前日比
- 出来高
- 取得日

### シグナルカード

- total_score
- news_score
- macro_score
- disclosure_score
- sentiment
- 最終更新日時

### AI分析サマリー

- 銘柄全体の直近分析
- 短期的な材料
- 注意すべきリスク
- 判断根拠

### ポジティブ/ネガティブ材料

- 材料タイトル
- impact_score
- time_horizon
- 関連ニュース

### 関連ニュース

- 公開日時
- タイトル
- sentiment
- impact_score
- AI要約
- 配信元
- URL

### 日足チャート

- 日足終値推移
- 出来高

## 9.5 レイアウト案

```text
/stocks/NVDA

[NVDA - NVIDIA Corporation]
NASDAQ / Technology / USD

┌────────────┬────────────┬────────────┐
│ Latest     │ Change     │ Signal     │

┌────────────────────┬────────────────────┐
│ ポジティブ材料       │ ネガティブ材料       │

│ +6 DC需要拡大       │ -3 高PER警戒        │

[関連ニュース]
┌────────────┬────────────┬────────┬────────────────────┐
│ Date       │ Sentiment  │ Impact │ Title              │
├────────────┼────────────┼────────┼────────────────────┤

└────────────┴────────────┴────────┴────────────────────┘

[日足チャート]
```

## 9.6 優先順位

画面内の表示優先順位は以下とする。

1. 銘柄ヘッダー
2. シグナルスコア
3. AI分析サマリー
4. ポジティブ/ネガティブ材料
5. 関連ニュース
6. 日足チャート
7. 株価履歴

## 9.7 禁止表現

画面上では、以下のような売買推奨表現は使用しない。

- 買い
- 売り
- 今買うべき
- 売却すべき
- 明日上がる
- 必ず上昇する

代わりに以下を使用する。

- Strong Positive
- Positive
- Neutral
- Negative
- Strong Negative
- 強いポジティブ材料
- ややポジティブ
- 中立
- ややネガティブ
- 強いネガティブ材料

# 16. MVPでの認証方針

個人用アプリではあるが、Laravel Breezeによる認証機能を導入する。

## 16.1 理由

- 本番環境に配置しても最低限保護できる
- ウォッチリストやメモをユーザーに紐づけられる
- 将来的に複数ユーザー対応しやすい
- Laravel標準構成に近く実装しやすい

## 16.2 MVPで必要な認証機能

- ログイン
- ログアウト
- ユーザー登録
- パスワードリセット
